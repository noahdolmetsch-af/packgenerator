# Pack Generator: instructions for Claude

Personal tour-preparation PWA for Noah: plan, pack, ride, debrief, bike care. It is built with Svelte 5, Vite and Dexie (IndexedDB) and works offline. It is live on GitHub Pages; each PR also gets a Vercel preview.

Noah writes German and is not a developer. Write replies to him in simple German, and explain GitHub steps click by click. Since 24.11.2026 (Noah «aktuell immer eher zu knapp», Block 2 in `docs/regeln.md`) replies are fuller, not terse: say what happened, why, what it means for him and what comes next, in whole sentences. Every message links its thread, names the topic in words and explains every PR number in words, never numbers or abbreviations alone (Block 2). The app's source language is English, and the German texts go through `t()`.

**Before every request, read two files:**
1. `docs/app-stand.md` (Noah 03.11.2026: «jeder thread soll das und alles weitere projektrelevante immer vor jeder abfrage berücksichtigen»). It lists what the app can do, with the link of every function, the places, the data and the connections. Do not analyse again what it already says. If the code differs, the code is right and your PR corrects the file; `tests/appstand.test.js` fails on a dead link or a function that sits under no row.
2. `docs/regeln.md`, **the one source of the working rules, in nine blocks** (1 measure, 2 how I write to Noah, 3 who does what, 4 PRs and queue, 5 approval and merge, 6 after the merge, 7 tests, 8 private and free, 9 keeping it current). Every block has its date and source; it is one page. This file holds no working rules of its own; it holds the rules for the code. Noah's newest message in the thread beats both files. Older and replaced rules sit only in `docs/regeln-archiv.md`.

## Rules for the code

- **Groups everywhere** (Noah, 18.10.2026 «grundsätzlich überall»): every group the user sees or chooses can be renamed and deleted. Deleting asks where the contents go, with «Ohne Gruppe» preselected, and then offers Undo. It never deletes the contents. Names the user typed never go through `t()`. A new kind of group comes with rename and delete and goes in `GROUP_PLACES` (`src/lib/groups.js`), which the guard test `tests/groups.test.js` checks. Use `src/lib/ui/GroupDeleteSheet.svelte` for the delete question.
- **Never cut off** (Noah «a und b» 24.11.2026 23:38, Block 1 in `docs/regeln.md`): every window, sheet and popup fits the screen. Header and footer stay fixed, the main button («Fertig») lives in the footer, only the middle scrolls, and a soft shadow at the bottom edge shows that more follows. No button may be clipped at an edge. Use the shared sheet component for new windows instead of writing own fixed heights; the guard test opens every window at phone 390, laptop 1440×800 and desktop 1440×900 and checks that the main button is fully inside the viewport and no button is clipped (Block 7).
- **Pages load later** (Tempo, 19.10.2026): only Heute (`Home.svelte`) is imported at the start. A new page goes into `PAGES` in `src/App.svelte` as `Name: () => import('./pages/Name.svelte')` and is shown with `<LazyPage load={PAGES.Name} />` (`src/lib/nav/lazy.js`). Big tools (PDF, text recognition, image models, video) load with `await import()` on first use. The build stops when a JS file passes 3 MB (`scripts/size-guard.mjs`, guard test `tests/size-guard.test.js`).
- **Change everything yourself** (Noah, 19.10.2026 «alle daten können vom nutzer selber hinzugefügt, umbenannt oder gelöscht werden»): every kind of data the user sees can be added, renamed and deleted in the UI. **Delete (rule changed 24.11.2026, Noah «4a» on 23.11.2026 19:49, `docs/decisions/loeschen-rueckgaengig.md`):** what is quickly made again (an idea, a life phase, a weight, a place in a list, a photo) is deleted at once and offers Undo for 8 seconds (`UNDO_MS`, `offerDone`); things with a history (a question with answers, a group with contents, a bike, a tour) ask first in the app's own window (`askDelete`, never `confirm()`) and then offer Undo (`deleteWithUndo`). When unsure, ask. `confirm()` stays forbidden. Nothing is blocked because it is still used: the delete window asks where the dependent things go (e.g. a bike's trips, `src/lib/bikedelete.js`). App lists live in «Listen und Typen» (`STANDARD_LISTS` in `src/lib/standard.js`, applied in `src/lib/lists.js`). Open gaps: `notes/alles-bearbeiten/README.md` in the project folder.
- **Content first** (Noah 21.11.2026 «5a»; user criterion in Block 1 of `docs/regeln.md`): help never stands before the content of a page. A page starts with what the user came for. Help is one closed line («Was du hier tun kannst» opens the «?» window, Noah 22.11.2026 «so lassen – immer zugeklappt», and it stays) and «Alle Funktionen von …» at the page end (V7). No new card, tile field or hint line above the content; a hint line inside the content only on Heute. A new function's jump-off and «Gut zu wissen» go into these existing help places (a «Passt hier» row, the «?» window, the line at the page end), never as a new block on top. This loosens Fertig-Regel points (2) and (3): they are met by those places.
- **Course check:** `docs/vorhaben.md` lists every planned project with its why and goals. Before starting, check it serves Klarheit, Auffindbarkeit and the Leitfaden (Block 1; the old «six goals» are no longer the measure, Noah 24.11.2026); if not, ask Noah. Once a week, the Sunday brief carries a short course check with a/b questions.

## Every PR

## Tests

(The rules about tests are Block 7 in `docs/regeln.md`; here are the commands and the technical details. Before a PR that changes a page, search `tests/` for every test that touches that page, also from other areas, and run them locally.)

- `npm test`: vitest.
- `npx playwright test <spec> --workers=1`, with `E2E_PORT=52xx` and `E2E_SKIP_GESAMTTEST=1`, for your own specs plus `tests/e2e/guard.spec.js`. In the cloud container: `PW_CHROMIUM=/opt/pw-browsers/chromium` and `--trace off`.
- A PR first runs only `build` and `e2e (desktop)` (the Wächter). The label `ok` starts `e2e (phone)` (5 parts); it runs only the specs of the pages the PR touches (`scripts/ci-map.mjs`, from the app's own imports, plus the Kern `flow.spec.js` and `guard.spec.js`); a file every page loads, an unclear case, build or workflow files run everything, docs/news/German text files alone run none. **«Schwer» PRs** (data, backup, sync, storage, `api/`, build and workflow files, anything `scripts/ci-scope.mjs` does not understand; it prints `schwer=yes`) run only the quick stage with `ok` (the Kern, their own pages, the data specs) and `e2e (phone)` stays red with «Schwerer PR … Label «voll» setzen»; put the label `voll` on such a PR right before the merge, that runs all five parts once (Noah 24.11.2026 «a»). A push after `voll` runs all five parts again, so push first, then set `voll`. Merge only when `e2e (phone)` ran green on the current head (for a Schwer PR: with `voll` on). The night run is the safety net.
- To run one shard by hand: `npx playwright test tests/e2e/gesamttest --project=desktop --shard=1/2 --workers=2`.
- Tests read their lists (blocks, categories, labels) from the app source instead of keeping copies.
- Afterwards run `git checkout -- qa/` (tests write screenshots there).
- Test dates use calendar-day arithmetic in Europe/Zurich, never `Date.now() + n*864e5`. Test titles are ASCII only (no ü ä ö « »).
- For «today» in app code, use `localDay()` (src/lib/localday.js), not `toISOString().slice(0,10)`.
- **Flaky tests** (lessons from 24 cases, 23./24.11.2026; the list of known ones is in the memory file `build-regeln-flakes-lessons`): first run with `--workers=1` to see whether the order is the cause; a test near the 90-second limit is split, the limit is never raised; several red tests of the same width have one common cause; PR branches stay linear. A test that fails twice by chance goes on the list and is made stable the same day.
- **Full check** only once per heavy PR, at the end: **live since 24.11.2026** (PR 1679, thread «Tests schneller machen»). Heavy = data, backup, sync, storage, `api/`, build and workflow files, anything unclear (the definition is `scripts/ci-scope.mjs`). Until the label «voll» is on the PR, only the quick stage runs (Kern, own pages, data specs); the label is set right before the merge, **push first, then set «voll»** (a push afterwards starts the quick stage again).
